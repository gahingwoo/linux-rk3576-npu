What ran
  The radxa-rock-4d image from the same fork CI run as r422 (gahingwoo/build
  run 41257131442, branch rk3576-npu-ci): Armbian trunk 26.11, trixie
  minimal, 7.3.1-edge-rockchip64, Armbian's rockchip64-7.3 patches plus all
  15 patches of v14. The patch directory is identical to the branch of
  armbian/build pull request #11163. Image sha256 97651dbba4ebf227...
  Written to an SD card with dd, read back identical over 2462056448
  bytes. The card previously held an Armbian 26.8.2 desktop; its home
  directory was backed up first. 11 GB board.

The NPU
  /dev/accel/accel0, rocket probes both cores, genpd npu/nputop/npu0/npu1
  registered and off at idle, NPU clock 594000000 Hz. The same single new
  boot line as on the CM5-IO (r422): device link with supplier 1-0023 for
  power-domain@0. No SError, no IOMMU fault.

charsiu

  also found a fourth installer bug: the image has no git, the bootstrap
  took a tarball, and every version stamp said "unknown"; the first
  regression then passed section 3 with "both arms unknown". Fixed in
  charsiu 3358698 (the tarball's commit is resolved and recorded, and an
  unknown arm is refused). The regression below is on that build, installed
  as a tarball on this board with no git present.
