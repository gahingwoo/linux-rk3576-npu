r411 shipped four overlaps and then measured the fp16 attention threshold with

1. ⛔ THE SCRIPT WOULD HAVE PRINTED 1.000 AND MEANT NOTHING
---------------------------------------------------------------------
board_attn_npu.sh compared "the empty environment" against CHARSIU_ATTN_NPU=1,
and the empty environment WAS the CPU arm for as long as off was the default.
r411 made `auto` the default. From that moment the empty environment is a
third thing: the CPU arm below 448 tokens and the NPU arm above it.

Run unchanged at the lengths this round cares about, it would have put the NPU
arm in both columns at 452 and up and reported a ratio of 1.000 -- a null
result that looks like a measurement. The CPU arm is CHARSIU_ATTN_NPU=0 now
and the header says which two arms ran.

🔑 1) THE RULE THIS TREE ALREADY HAS: both arms must name the knob. What is new
is that a script can pass that rule on the day it is written and fail it later,
because the DEFAULT moved underneath it. Changing a default is an edit to every
script that took it as an arm.

3. ⭐⭐ AND SECTION 1 EXPLAINS r411's 452 ROW, WHICH READ THE OTHER WAY
---------------------------------------------------------------------
r411 section 8 measured the same arm on the same boot with the same binary and

    tokens    r411 CPU   r411 NPU   ratio      r412 CPU   r412 NPU   ratio
       302        2274       2202   0.968          2138       2088   0.977

⭐ 5) THE 452 ROW IS NOT NOISE, IT IS THE ARM THAT WAS NOT NAMED. r411 ran
board_attn_npu.sh before the correction in section 1, so its "CPU" column was
the EMPTY environment -- and the empty environment is `auto`, which turns the

against 2138, same boot, same binary, clock pinned. r411's cell is two repeats

tighter spread and the stated arm is the one to carry forward, and the gap is
recorded rather than explained away -- it is larger than the 2.2% cross-boot

4. ⛔⛔⛔ AND THE THRESHOLD IS WRONG IN THE OTHER DIRECTION TOO
---------------------------------------------------------------------
Phi-3.5-mini at 352 tokens, three repeats an arm, arms alternating:

    Phi-3.5-mini-instruct-Q4_0   351   CPU 8768 (8693..8812)
                                       NPU 10158 (10128..11214)
                                       margin -15.9%, spread 1.4%   NPU LOSES

1390 ms, against a 1.4% spread on the arm it is measured against. That is not
noise and it is not a tie.

⛔ 7) SO THE SHIPPING DEFAULT IS COSTING PHI RIGHT NOW. attn_npu_min_tokens is
448, so every Phi prompt from 448 tokens up runs its attention on the NPU --
and at 352 that arm is 1.4 seconds behind. r411's ten model table has Phi at
-0.3% at 852, so Phi's crossover is somewhere near 852 and the default turns
the arm on 400 tokens before it.

One number cannot be both 320 and 850. A length threshold is the wrong SHAPE
for this decision.

🔑 8) AND THE MECHANISM IS GQA, WHICH IS A PREDICTION AND NOT A FIT. The mirror
costs one pack per position per layer per KV head -- it scales with the KV
cache. The attention it buys scales with the QUERY heads. So the return on a
mirror byte is n_head / n_kv_head:

    Llama-3.2-1B    32 heads,  8 kv   gqa 4     crossover measured ~320
    Phi-3.5-mini    32 heads, 32 kv   gqa 1     crossover measured near 852
    gemma-3-1b       4 heads,  1 kv   gqa 4     PREDICTS ~320: wins at 352
    Qwen3-0.6B      16 heads,  8 kv   gqa 2     PREDICTS ~640: loses at 352

⚠ THE TWO PREDICTIONS ABOVE WERE WRITTEN BEFORE THEIR ROWS RAN. Two points
always fit a line and this tree has been burned by exactly that three times;
the only thing that makes gqa more than a story is that it says what the next
two rows will do before they do it. If gemma-3 and Qwen3 come back the other
way, gqa is dead and the threshold has to be measured per model.

⛔ 9) QWEN3 WAS PREDICTED TO LOSE AND IT WINS BY 7.7%. The quantitative form of
the gqa story -- crossover proportional to 1/gqa, so gqa 2 crosses at 640 --
is dead. It was an invented constant of proportionality with one point behind

🏁 10) THE QUALITATIVE FORM SURVIVES AND IT SEPARATES ALL FIVE:

    gqa 1    Phi-3.5-mini  32/32      SmolLM2-1.7B  32/32        both LOSE
    gqa 2    Qwen3-0.6B    16/8                                  wins
    gqa 4    Llama-3.2-1B  32/8       gemma-3-1b     4/1         both win

The two losers are exactly the two models with no GQA, and nothing else in the
five separates them: the losers are not the largest (SmolLM2-1.7B is smaller
than Phi and larger than Qwen3), not the deepest, not the widest head.

The mechanism says why in one line: the mirror costs one pack per position per
layer per KV head and the attention it buys is done per QUERY head, so a model
that shares no KV head across queries pays the full mirror for the least work.

⚠ 11) FIVE POINTS ARE STILL FIVE POINTS. What is measured is that the two gqa 1
models lose at 352 and the three others win; what is NOT measured is where any
of them crosses. A rule that says "gqa 1 is different" is the smallest claim
the data supports and even that has two models behind it.

6. ⭐ WHERE PHI'S 1390 ms GOES, READ OFF THE RUNTIME'S OWN COUNTERS
---------------------------------------------------------------------
Phi-3.5-mini, 351 tokens, CHARSIU_ATTN_NPU=1, CHARSIU_STAGES=1:

    charsiu: fp16 attention ran 160 layers, fell back on 0, refused 0
    charsiu:   of 804 ms in the layer: kv surfaces 123  scores group 222
               softmax 0 (pooled)  values group 458  unaccounted 0 ms
    charsiu:   V surface ladder: 32 64 128 256 352
               (4 repacks, 595 ms: 402 in alloc, 192 in block copy)

⭐ 12) 402 ms OF THE LOSS IS THE ALLOCATOR AND NOTHING ELSE. The growth is
OUTSIDE the layer clock on purpose, so 804 + 595 = 1399 ms is what the arm
costs and 1390 ms is what it lost -- the two agree to 9 ms, which means the
loss is fully accounted and there is no fourth thing to look for.

Four rungs, and each one frees and allocates n_layer * n_kv buffer objects.
Llama-3.2-1B has 16 * 8 = 128 of them; Phi has 32 * 32 = 1024. Same ladder,
eight times the objects.

🔑 13) SO THE ANSWER IS NOT A THRESHOLD, IT IS THE ALLOCATION. A surface
allocated once at the prompt's ceiling can climb the ladder WHERE IT LIES: the
padded extent appears in one term of the offset, so a rung is a block move, and
a block move can be done in place if the groups are walked from the top down.
charsiu_fp16_regrow_vcols does that now, charsiu_fp16_w_set_k records the new
layout, and tests/fp16_regrow.c holds the in place arm against the same
reference as the copying one over 1584 shapes.

⛔ 14) AND THE FIRST CUT OF IT WAS WRONG IN A WAY ONLY THE TEST SAW. A block
that moves up leaves its own old copy behind, inside the block above it in the
new layout. The copying arm never noticed because its destination was a fresh
calloc; in place, -1.0 sat where the reference had zero, on every shape whose
live count was under the extent. The bytes looked like a plausible surface.

7. 🏁🏁 THE GROWTH LINE IS THE PROOF, AND IT IS NOT A TTFT READING
---------------------------------------------------------------------
Phi-3.5-mini, 351 tokens, CHARSIU_ATTN_NPU=1, the two binaries on one boot:

    charsiu_run_win   ladder 32 64 128 256 352  (4 repacks, 595 ms:
                      402 in alloc, 192 in block copy)
    charsiu_run_room  ladder 32 64 128 256 352  (4 repacks,  31 ms:
                      0 in alloc, 31 in block copy;
                      4096 of 4096 surfaces moved in place)

🏁 15) 595 ms -> 31 ms, SAME LADDER, SAME FOUR RUNGS. The allocator's 402 goes
to zero because nothing is allocated, and the block copy's 192 goes to 31
because it is no longer interleaved with 1024 frees and 1024 allocations per
rung evicting everything it touched.

⚠ 16) THE TTFT SAYS THE SAME THING AND SAYS IT WORSE, which is why the growth
line is the reading quoted:

    A (win)   9679 ms   9407..10522     spread 11.5%
    B (room)  9027 ms   8980..9041      spread  0.7%

+6.7% at the median, and by this tree's own rule that does NOT clear A's own
spread, so the pair is "level". What it does do is separate completely: B's
worst reading beats A's best by 366 ms. Three against three with no overlap is
one arrangement in twenty, which is suggestive and is not the evidence. The
evidence is 595 -> 31 on a counter that TTFT noise cannot reach.

🔑 17) AND A'S 11.5% SPREAD IS ITS OWN FINDING. Three readings of one binary,
one boot, clock pinned, governor pinned: 9407, 9679, 10522. That is five times
the 2.2% cross-boot drift this tree quotes as its noise bound, on the arm that
allocates 1024 buffer objects four times. tests/board_drift.sh exists to say
whether that is Phi, the allocator, or the board.

`read` is 3176.8 ms of the 5678 ms int4 matmul entry on Phi -- 56%, the

11. 🔑 AND THE ROUND STAMPS ITS OWN COMMIT NOW
---------------------------------------------------------------------
Every board round in this tree has recorded the machine, the NPU clock, the
boot id and the binary's mtime. None has recorded the COMMIT, because
/opt/charsiu is not a git checkout and neither is /root/charsiu_run_<name>,
which is how a board binary actually arrives. So a round's numbers were tied to
a version by somebody remembering which file they had copied.

That is not a hypothetical. This round's own section 3 is a table whose two
readings of one cell disagree by 6.4%, and the first thing anybody would want
to know is whether the two came from the same build. The mtimes said the same
day.

  - the commit is compiled into every binary (Makefile -DCHARSIU_BUILD from
    `git describe --always --dirty`), so `charsiu_run --version` answers it
    wherever the file has been copied to and under whatever name;
  - `charsiu_build` in tests/board_clk.sh reads it back, and 14 board scripts
    print a `build` line -- including board_vendor.sh and board_text_all.sh,
    which had no clock helper at all and are the two the round of record uses;
  - the installer writes $BIN/COMMIT, so an install can be identified even when
    the binary that ran came from somewhere else.

⚠ -dirty IS PART OF THE ANSWER. A binary built from an edited tree is not the
commit it names, and stripping that would make the stamp worse than nothing.

⚠ AND A BINARY TOO OLD TO ANSWER SAYS SO. charsiu_build prints "no --version
(binary predates the stamp)" rather than an empty string, because an empty
string is exactly what an unmounted debugfs looked like in r411 and it cost a
whole TTFT ladder.
